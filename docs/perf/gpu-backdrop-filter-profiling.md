# Профилирование: интерфейс держит GPU на 100%

**Дата:** 13 сентября 2026
**Стенд:** macOS, Chrome, дисплей 160 Гц / HiDPI, инстанс `http://umbrel.local:8998`
**Ветка с фиксом:** `fix/gpu-backdrop-filter`

---

## 1. Симптом

На некоторых страницах (ярче всего — Библиотека), особенно если «посидеть подольше»,
поводить мышью или походить по разделам, видеокарта уходит в полку.

## 2. Что именно измерялось

Загрузка GPU на macOS снимается напрямую из драйвера, без DevTools:

```sh
ioreg -r -d 1 -w 0 -c IOAccelerator | tr ',' '\n' | grep 'Device Utilization'
```

Параллельно снималась загрузка CPU (`top -l 1`) и времена кадров в самой странице
(`requestAnimationFrame`-семплер), плюс инвентаризация DOM: `getAnimations()`,
число видимых элементов с `backdrop-filter`, счётчики `setInterval` / слушателей.

## 3. Первый замер — в момент, когда «долбилось»

```
"Renderer Utilization %" = 99
"Device Utilization %"   = 99

CPU usage: 9.30% user, 12.48% sys, 78.20% idle
```

**Вывод:** это не JavaScript. CPU практически простаивает, нагрузка целиком
в GPU-процессе Chrome — то есть композитинг/растеризация, а не логика приложения.

## 4. Что было исключено

Проверялось в первую очередь как «классика жанра» — и не подтвердилось:

| Гипотеза | Проверка | Результат |
|---|---|---|
| Утечка `setInterval` при переключении вкладок | 12 полных обходов всех 10 разделов с обёрнутым `setInterval`/`clearInterval` | активных таймеров стабильно 1, утечки нет |
| Рост DOM при навигации | счётчик элементов после каждых 3 кругов | 5311 → 7495 и **плато**; все панели просто остаются в DOM, утечки нет |
| Утечка слушателей | обёрнутый `addEventListener` | +35 `tr:click` за 60 переключений, пересоздаются вместе со строками таблицы |
| Долгие задачи JS | `PerformanceObserver({entryTypes:['longtask']})` | 0 longtask за период наблюдения |
| Тяжёлые `requestAnimationFrame`-циклы | поиск по `app.js` | всего 2 вызова, оба одноразовые |

## 5. Найденная причина

### 5.1. `backdrop-filter` на постоянных крупных поверхностях

`backdrop-filter` заставляет Chromium на каждый кадр заново снимать подложку
элемента и прогонять её через отдельный проход размытия. Пока под элементом
что-нибудь меняется — этот проход повторяется каждый vsync.

На странице Библиотеки в табличном режиме такие поверхности постоянно присутствовали
в дереве отрисовки:

| Элемент | Размытие | Размер |
|---|---|---|
| `aside.sidebar` | `blur(12px)` в Classic | во всю высоту вьюпорта |
| `div.table-responsive.glass-table-wrap` | `blur(16px)` | 1688 × 429 |
| `div.release-drawer-overlay` | `blur(6px)` | весь вьюпорт, **даже когда дровер закрыт** |
| `aside.release-drawer-panel` | `blur(24px)` | 580 × 1197, **даже когда дровер закрыт** |

Всего по проекту было 81 активное объявление: 76 в `web/css/style.css` и ещё 5
в `wiki.html`, `api-docs.html`, `quality-guide.html`.

### 5.2. Триггер — спиннер фоновых задач

Постоянный источник инвалидации нашёлся в футере сайдбара:

```
div#tasks-spinner.tasks-spinner   ← animation: taskSpin 0.8s linear infinite
  div#tasks-status-pill
    div#tasks-status-widget.has-running
      div.sidebar-footer
        aside.sidebar                ← backdrop-filter: blur(28px), высота вьюпорта
```

Спиннер размером **15 × 15 px** живёт внутри элемента с размытием во всю высоту
экрана. Пока крутится спиннер (а он крутится всё время, пока висит хоть одна
фоновая задача), сайдбар переразмывается каждый кадр — 160 раз в секунду на
160-герцевом HiDPI-дисплее.

Отсюда и «если долго посидеть»: фоновая задача стартует сама, пользователь ничего
не делает, а GPU уже в полке. Движение мышью и переходы по разделам добавляют
свои инвалидации (hover-переходы, перерисовка сеток по опросам раз в 3–15 с).

## 6. A/B на живом инстансе

Воспроизводимый стимул: один маленький элемент, бесконечно ездящий по контенту
(эквивалент «вожу мышкой»). Замер — среднее `Device Utilization %` за 8–12 секунд.

### Факторный эксперимент

| Конфигурация | GPU |
|---|---|
| как есть | **99 %** |
| `box-shadow: none` везде | 85 % |
| `backdrop-filter: none` везде | 42 % → **18 %** после исключения постороннего оверлея |
| и то и другое выключено | 13 % |

> Первые прогоны давали завышенный вклад `box-shadow`: в замер попадал
> полноэкранный анимированный оверлей расширения Claude in Chrome
> (`#claude-agent-glow-border`, `box-shadow` 2560 × 1197 + бесконечная анимация).
> После его исключения картина однозначная: практически вся нагрузка — `backdrop-filter`.

### Проверка по одному элементу

`backdrop-filter` оставлен **только** на сайдбаре, со всех остальных снят:

| Конфигурация | GPU |
|---|---|
| только `.sidebar`, `blur(28px)` | 99 % |
| только `.sidebar`, `blur(6px)` | 99 % |

**Радиус размытия почти не важен.** Дорог сам факт наличия `backdrop-filter`
на большой поверхности: отдельный снимок подложки и отдельный проход растеризации
на каждый кадр. Одного элемента достаточно, чтобы загнать GPU в полку.

### Проверка табличного режима

Отдельно воспроизведено движение указателя по пяти строкам Библиотеки со скоростью
около четырёх смен строки в секунду. Здесь использовалась загрузка GPU-процесса
Chrome как относительная метрика композитинга, поэтому эти значения нельзя напрямую
сравнивать с процентами `ioreg` выше:

| Конфигурация | Среднее | Максимум |
|---|---:|---:|
| стекло включено | 39,1 | 46,7 |
| стекло выключено | 25,8 | 37,1 |
| стекло включено, без transition у строк | **2,1** | **2,8** |

Причиной оставшейся нагрузки оказался `transition: background 0.15s` у строк
стеклянных таблиц: каждый переход указателя запускал новую анимацию большой области.

## 7. Фикс

`web/css/style.css`, `web/index.html`, `web/js/app.js` + три статические страницы.

1. Все 81 активное объявление приведено к виду

   ```css
   backdrop-filter: var(--glass-blur, blur(28px));
   ```

   с глобальным выключателем:

   ```css
   :root { --glass-blur: none; }
   :root[data-glass="on"] { --glass-blur: initial; }
   ```

   Когда стекло выключено, `--glass-blur: none` наследуется всем элементам.
   Когда включено — свойство сбрасывается в guaranteed-invalid (`initial`),
   и каждое объявление подставляет **свой собственный** радиус из fallback-значения.
   Дизайн при включённом стекле сохраняется в точности, ни один радиус не потерян.

2. По умолчанию стекло **выключено**. Переключатель:
   Настройки → Общие → Интерфейс → «Эффекты стекла», хранится в
   `localStorage["aliasarr_glass"]`, применяется атрибутом `data-glass` на `<html>`
   ещё до первой отрисовки (в bootstrap-скрипте, как тема и скроллбары).

3. Закрытый дровер релизов убран из дерева отрисовки (`visibility: hidden`
   с задержкой перехода, чтобы сохранить анимацию закрытия) — раньше это был
   постоянный полноэкранный слой с размытием за краем вьюпорта.

4. У строк стеклянных таблиц отключён `transition`. Цвет hover и выбранной строки
   сохранён, но меняется мгновенно и не создаёт серию композитных кадров при движении
   указателя по таблице.

## 8. Верификация

Пропатченный `style.css` подставлен в **живую** страницу инстанса вместо штатного,
стимул и методика замера те же:

| Состояние | Видимых элементов с `backdrop-filter` | GPU |
|---|---|---|
| `data-glass="off"` (новое умолчание) | 0 | **16 %** |
| `data-glass="on"` (контроль) | 4 | 59 % |
| до фикса | 5 | 99 % |

Переключатель проверен на полной сборке (`index.html` + `app.js` + `style.css`):

* `data-glass` выставляется до первой отрисовки, `--glass-blur` = `none`;
* `applyGlassMode('on')` → `.sidebar` получает ровно свой исходный радиус
  (`blur(28px)` в Vanguard, `blur(12px)` в Classic), значение пишется в
  `localStorage`, `<select>` синхронизируется;
* локализация ru/en на месте;
* закрытый дровер — `visibility: hidden`, открытый — `visible`, анимация цела;
* при выключенном стекле в документе **ноль** живых элементов с `backdrop-filter`;
* движение по строкам таблицы больше не запускает фоновые CSS-переходы.

## 9. Если захочется вернуть «стекло»

Настройки → Общие → Интерфейс → «Эффекты стекла» → «Включено». Дизайн вернётся
один в один, вместе с нагрузкой на GPU. Разумный компромисс на будущее — оставить
размытие только на модальных оверлеях и тостах, а постоянные поверхности
(сайдбар, липкая шапка, обёртки таблиц) держать непрозрачными: они и так залиты
фоном с альфой 0.88–0.94, визуально разница почти незаметна.
